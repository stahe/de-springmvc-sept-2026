    3. Das Action-Modell

    Eine Action benötigt die vom Browser gesendeten Informationen: die Parameter der URL ([?name=martin&age=42]), die Formularfelder, den JSON-Body der Anfrage und manchmal einen HTTP-Anfrage-Header. Der Originalkurs bezeichnet die Gesamtheit dieser Informationen als Modell der Action. Dieses Kapitel zeigt, wie [Spring MVC] der Action diese Informationen bereitstellt, sie in den richtigen Typ konvertiert und validiert. Dieser Vorgang heißt Datenbinding ([data binding]).

    Anmerkung zur Terminologie: In [Spring MVC] bezeichnet das Wort „Modell“ ([Model]) in erster Linie die Daten, die eine Action an ihre View übergibt (Kapitel 4, „Die View und ihr Modell“). Das Modell einer Action im Sinne dieses Kapitels ist das, was sie empfängt.

    Die Beispiele 07 bis 12 sind wie die des vorherigen Kapitels [Maven] -Module aus dem Ordner [examples]. Sie können eines davon ausführen, indem Sie in diesem Ordner ein Terminal öffnen und [../mvnw spring-boot:run] eingeben ([..\mvnw spring-boot:run] unter [Windows]); [Ctrl-C] beendet den Server.     package example07.controllers;

import java.util.Map;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/parameters")
public class ParametersController {

    // /parameters/action01?name=martin: der URL-Parameter [name] -> der Action-Parameter [name]
    // required = false: der Parameter darf fehlen, er ist dann null
    @GetMapping("/action01")
    public String action01(@RequestParam(required = false) String name) {
        return "name = [%s], of type %s".formatted(name, name == null ? "null" : name.getClass().getSimpleName());
    }

    // /parameters/action02?age=42: der Wert wird in den Parametertyp KONVERTIERT;
    // ohne required = false ist der Parameter obligatorisch
    @GetMapping("/action02")
    public String action02(@RequestParam int age) {
        return "age = [%d], of type int".formatted(age);
    }

    // /parameters/action03?age=42: Integer (und nicht int) akzeptiert den Wert null
    @GetMapping("/action03")
    public String action03(@RequestParam(required = false) Integer age) {
        return "age = [%s]".formatted(age);
    }

    // /parameters/action04?page=2: ein Standardwert, falls der Parameter fehlt
    @GetMapping("/action04")
    public String action04(@RequestParam(defaultValue = "1") int page) {
        return "page = [%d]".formatted(page);
    }

    // /parameters/action05?q=spring: der Name des URL-Parameters, wenn er abweicht
    @GetMapping("/action05")
    public String action05(@RequestParam(name = "q", required = false) String search) {
        return "search = [%s]".formatted(search);
    }

    // /parameters/action06?name=martin&age=42: alle Parameter auf einmal
    @GetMapping("/action06")
    public Map<String, String> action06(@RequestParam Map<String, String> parameters) {
        return parameters;
    }
}

    Lassen Sie uns diesen Code kommentieren:

    • Zeilen 16–17: Die Annotation [@RequestParam] verknüpft einen Parameter der Action mit einem Parameter der URL (dem Teil nach dem [?], bekannt als Query-String bzw. [query string]). Sofern nichts anderes angegeben ist, hat der Parameter in der URL denselben Namen wie der Parameter in [Java]: [name]. Dieser Name ist zur Laufzeit nur deshalb bekannt, weil das übergeordnete Projekt von [Spring Boot] den Compiler anweist, ihn im kompilierten Code beizubehalten (Option [-parameters]). Eine Annotation kann benannte Argumente akzeptieren, die Attribute genannt werden: [required = false] gibt an, dass der Parameter fehlen darf; in diesem Fall entspricht er [null]. Zeile 18: Die Methode [formatted] ersetzt jedes Vorkommen von [%s] in der Zeichenkette durch das folgende Argument; [name.getClass().getSimpleName()] ist der Kurzname des Typs des Werts;
    • Zeilen 23–24: Der Parameter ist als Typ [int] deklariert: [Spring MVC] wandelt die empfangene Zeichenkette (["42"]) in eine Zahl um. Ohne das Attribut [required = false] macht [@RequestParam] den Parameter erforderlich: Das ist der Standardwert für [required]. Ein fehlender Parameter oder einer, dessen Umwandlung fehlschlägt, führt zu einem 400-Fehler, und die Action wird nicht ausgeführt;
    • Zeilen 29–30: Ein [int] kann nicht gleich [null] sein. Für eine optionale Zahl wird der Parameter mit dem Typ [Integer] deklariert, der Klasse [Java], die ein [int] „umhüllt“ ([wrapper]): Ein [Integer]-Objekt kann den Wert [null] haben, was die Unterscheidung zwischen „kein Alter“ und „Alter 0“ ermöglicht;
    • Zeilen 35–36: Das Attribut [defaultValue] liefert den Wert, der verwendet wird, wenn der Parameter fehlt (es macht den Parameter außerdem optional). Es handelt sich um eine Zeichenkette, die auf dieselbe Weise umgewandelt wird wie der empfangene Wert;
    • Zeilen 41–42: Das Attribut [name] gibt den Namen des Parameters der URL an, wenn er sich von dem des Parameters [Java] unterscheidet: Der Parameter [search] der Action erhält den Parameter [q] aus der URL;
    • Zeilen 47–48: Ein Parameter vom Typ [Map<String, String>] , versehen mit [@RequestParam] , erhält alle Parameter der URL ohne Umwandlung: ein Dictionary (Parametername, Wert). Die Action gibt es unverändert zurück, und [Spring MVC] serialisiert es in JSON.

    package example08.models;

import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;

// das Action-Modell: eine Klasse, deren Felder alle ihre Constraints tragen
public class PersonModel {

    @NotBlank(message = "the name is required")
    @Size(min = 2, max = 20, message = "the name must have 2 to 20 characters")
    private String name;

    @NotNull(message = "the age is required")
    @Min(value = 0, message = "the age must be between 0 and 150")
    @Max(value = 150, message = "the age must be between 0 and 150")
    private Integer age;

    @NotNull(message = "the title is required")
    @Pattern(regexp = "Mr|Mme|Melle", message = "unknown title")
    private String title;

    // optional: kein @NotNull
    @Email(message = "invalid email address")
    private String email;

    // die Accessoren (Getter und Setter): das Model Binding füllt
    // jedes Feld über seinen Setter; die JSON-Serialisierung liest es über seinen Getter
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public Integer getAge() { return age; }
    public void setAge(Integer age) { this.age = age; }

    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }

    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }
}

    • Zeilen 3–9: die Validierungsannotationen, alle im Paket [jakarta.validation.constraints];
    • Zeilen 14–16: Der Name ist erforderlich und darf nicht leer sein ([@NotBlank] weist [null], eine leere Zeichenkette und eine nur aus Leerzeichen bestehende Zeichenkette zurück) und muss zwischen 2 und 20 Zeichen lang sein ([@Size]). Jede Annotation akzeptiert eine benutzerdefinierte Fehlermeldung (Attribut [message]);
    • Zeilen 18–21: Das Alter wird in eine ganze Zahl umgewandelt, die erforderlich ist ([@NotNull]) und zwischen 0 und 150 liegen muss ([@Min], [@Max]). Es ist als [Integer] statt als [int] deklariert, damit „kein Alter“ ([null]) von [@NotNull] erkannt wird, anstatt auf 0 gesetzt zu werden;
    • Zeilen 23–25: Die Anrede muss dem regulären Ausdruck [Mr|Mme|Melle] entsprechen ([@Pattern]): Sie muss einer dieser drei Werte sein;
    • Zeilen 28–29: Die E-Mail-Adresse ist optional (kein [@NotNull]); falls vorhanden, muss sie gültig sein ([@Email]). Alle Bedingungen außer [@NotNull] und [@NotBlank] akzeptieren den Wert [null]: Das ist es, was ein Feld optional macht;
    • Zeilen 33–43: die Zugriffsmethoden. Per Konvention wird der Wert des Felds [name] von der Methode [getName] gelesen ([getter]) und von der Methode [setName] geschrieben ([setter]). Eine Klasse mit einem parameterlosen Konstruktor (hier dem von [Java] implizit bereitgestellten) und Zugriffsmethoden, die dieser Konvention folgen, heißt JavaBean. Das ist die Form, die das Data Binding erwartet: [Spring MVC] erzeugt das Objekt mit seinem parameterlosen Konstruktor und ruft dann für jeden Parameter der Anfrage den gleichnamigen Setter auf: [setName("martin")] für [?name=martin], nachdem der Wert in den Typ des Setters umgewandelt wurde. Der JSON-Konverter hingegen liest die Felder über ihre Getter.

import java.util.LinkedHashMap;
import java.util.Map;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import jakarta.validation.Valid;

@RestController
@RequestMapping("/persons")
public class PersonsController {

    // /persons/action01?name=martin&age=42&title=Mr
    // @Valid: das Modell wird validiert, BEVOR die Action läuft; ist es
    // ungültig, wird die Anfrage AUTOMATISCH abgelehnt (Fehler 400)
    @GetMapping("/action01")
    public Map<String, Object> action01(@Valid PersonModel person) {
        Map<String, Object> response = new LinkedHashMap<>();

        response.put("ageType", person.getAge().getClass().getSimpleName());

    // ausgeführt, und die Action entscheidet, was bei einem ungültigen Modell zu tun ist
    @GetMapping(value = "/action01", produces = MediaType.TEXT_HTML_VALUE)

import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.format.DateTimeParseException;
import java.time.format.ResolverStyle;

import org.springframework.core.convert.converter.Converter;

// ein Konverter: wandelt ein französisches Datum "23/09/2026" in ein LocalDate um.
// Er wird für JEDEN Parameter vom Typ LocalDate verwendet (siehe WebConfig)
public class DateFrConverter implements Converter<String, LocalDate> {

    // uuuu: das Jahr; STRIKT: "31/02/2026" wird abgelehnt (und nicht auf den 28. Februar zurückgesetzt)
    private static final DateTimeFormatter FORMAT =
            DateTimeFormatter.ofPattern("dd/MM/uuuu").withResolverStyle(ResolverStyle.STRICT);

    @Override
    public LocalDate convert(String text) {
        try {
            return LocalDate.parse(text, FORMAT);
        } catch (DateTimeParseException e) {
            // Fehlschlag: eine Exception, die Spring in einen Konvertierungsfehler umwandelt
            throw new IllegalArgumentException("[" + text + "] is not a valid dd/mm/yyyy date");
        }
    }
}

import org.springframework.core.MethodParameter;
import org.springframework.web.bind.support.WebDataBinderFactory;
import org.springframework.web.context.request.NativeWebRequest;
import org.springframework.web.method.support.HandlerMethodArgumentResolver;

// ein "Argument Resolver": er liefert den Wert der mit @Language annotierten Parameter,
// gelesen aus dem Header "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
public class LanguageResolver implements HandlerMethodArgumentResolver {

    // behandelt dieser Resolver diesen Parameter?
    @Override
    public boolean supportsParameter(MethodParameter parameter) {
        return parameter.hasParameterAnnotation(Language.class) && parameter.getParameterType() == String.class;

    // der Wert des Parameters
    @Override
    public Object resolveArgument(MethodParameter parameter, ModelAndViewContainer mavContainer,
            NativeWebRequest request, WebDataBinderFactory binderFactory) {
        String header = request.getHeader("Accept-Language");
        String first = header == null ? "" : header.split(",")[0].trim();
        return first.length() >= 2 ? first.substring(0, 2).toLowerCase() : "fr";
    }
}

    3.6.6. Fazit

    Das Action-Modell wird durch Binden von Daten der Anfrage aufgebaut: Parameter der URL und Formularfelder ([@RequestParam], Command-Objekt), der JSON-Body ([@RequestBody]), Header ([@RequestHeader]) und alles, was ein benutzerdefinierter Resolver liefern kann. Die Werte werden in den Typ des Parameters umgewandelt und anschließend gegen die Bedingungen von [Bean Validation] validiert, wenn das Modell mit [@Valid] annotiert ist. Ein Umwandlungsfehler bei einem [@RequestParam] oder ein ungültiges Modell ohne [BindingResult] führt zu einem 400-Fehler, ohne dass die Action ausgeführt wird: Das ist für einen JSON-Server angemessen. Bei einer HTML-Anwendung ist das Formular eine mit [@Valid] annotierte JavaBean, gefolgt von einem Parameter [BindingResult], den die Action abfragt (Beispiel 09), um das Formular mit seinen Fehlern erneut anzeigen zu können. Das ist das Thema des nächsten Kapitels.
