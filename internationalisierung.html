    5. Internationalisierung

    Eine internationalisierte Anwendung zeigt ihre Texte in der Sprache des Benutzers an. Die Fallstudie ist auf Französisch und Englisch verfügbar. Das Prinzip ist einfach: Die Views enthalten keinen Text mehr, sondern Schlüssel ([MENU.HOME]), und ein Wörterbuch pro Sprache ordnet jedem Schlüssel einen Text zu. Die gewählte Sprache wird in einem Cookie gespeichert.

    [Spring] hat ein eigenes Übersetzungssystem: das Interface [MessageSource], dessen Standardimplementierung Dateien wie [messages_fr.properties], [messages_en.properties] ... liest. Wir behalten das Interface bei, da [Spring] und [Thymeleaf] es für die Übersetzung verwenden, implementieren es aber selbst mit einer kleinen Klasse, die JSON-Wörterbücher liest: Es sind dieselben Dateien wie in den Versionen [ASP.NET Core MVC] und [NestJS] der Fallstudie, und ihr Format lässt sich ohne spezielle Werkzeuge lesen und schreiben. Die Auswahl der Sprache für jede Anfrage überlassen wir dagegen [Spring MVC]: Dafür ist sein Sprachresolver ([LocaleResolver]) zuständig, dem wir in Beispiel 16 begegnet sind.

    package example22.translation;

import java.io.IOException;
import java.io.InputStream;
import java.util.HashMap;
import java.util.List;
import java.util.Locale;
import java.util.Map;
import java.util.regex.Matcher;
import java.util.regex.Pattern;

import org.springframework.context.MessageSource;
import org.springframework.context.MessageSourceResolvable;
import org.springframework.core.io.ClassPathResource;
import org.springframework.stereotype.Component;

import tools.jackson.databind.JsonNode;
import tools.jackson.databind.ObjectMapper;

// der Übersetzungsservice: die JSON-Wörterbücher, EINMAL beim Start gelesen.
// Er implementiert das Spring-Interface MessageSource und heißt [messageSource]:
// Spring verwendet ihn dann für ALLE Übersetzungen und Thymeleaf für die
// Ausdrücke #{...} der Views.
@Component("messageSource")
public class Translator implements MessageSource {

    public static final List<String> LANGUAGES = List.of("fr", "en");
    public static final String DEFAULT_LANGUAGE = "en";

    // {name}: ein Parameter in einem Text
    private static final Pattern PARAMETER = Pattern.compile("\\{(\\w+)\\}");

    // Sprache -> (vollständiger Schlüssel "HOME.HELLO" -> Text)
    private final Map<String, Map<String, String>> dictionaries = new HashMap<>();

    public Translator() throws IOException {
        ObjectMapper json = new ObjectMapper();
        for (String language : LANGUAGES) {
            // die Wörterbücher liegen in src/main/resources/i18n, also im Classpath
            try (InputStream stream = new ClassPathResource("i18n/" + language + ".json").getInputStream()) {
                Map<String, String> dictionary = new HashMap<>();
                flatten(json.readTree(stream), "", dictionary);
                dictionaries.put(language, dictionary);
            }
        }
    }

    // die nächstliegende unterstützte Sprache zu [locale]: "fr_FR" -> "fr"; "de" -> "en"
    public static String language(Locale locale) {
        String language = locale == null ? "" : locale.getLanguage();
        return LANGUAGES.contains(language) ? language : DEFAULT_LANGUAGE;
    }

    // translate("HOME.HELLO", ["name", "Marie"], en) -> "Hello Marie!"
    // Die Parameter werden als Paare (Name, Wert) übergeben.
    public String translate(String key, Object[] parameters, Locale locale) {
        if (key == null || key.isEmpty()) {
            return "";
        }
        // ein fehlender Schlüssel zeigt den Schlüssel selbst an: ein Versäumnis ist auf dem Bildschirm sichtbar
        String text = dictionaries.get(language(locale)).getOrDefault(key, key);
        if (parameters == null || parameters.length == 0) {
            return text;
        }
        Map<String, String> values = new HashMap<>();
        for (int i = 0; i + 1 < parameters.length; i += 2) {
            values.put(String.valueOf(parameters[i]), String.valueOf(parameters[i + 1]));
        }
        // jedes {name} wird durch den Wert des gleichnamigen Parameters ersetzt
        Matcher m = PARAMETER.matcher(text);
        return m.replaceAll(r -> Matcher.quoteReplacement(values.getOrDefault(r.group(1), r.group())));
    }

    // { "MENU": { "HOME": "Home" } } -> { "MENU.HOME": "Home" }
    private static void flatten(JsonNode node, String prefix, Map<String, String> result) {
        for (Map.Entry<String, JsonNode> property : node.properties()) {
            String key = prefix.isEmpty() ? property.getKey() : prefix + "." + property.getKey();
            if (property.getValue().isObject()) {
                flatten(property.getValue(), key, result);
            } else {
                result.put(key, property.getValue().asString());
            }
        }
    }

    Gehen wir diesen Code durch:

    • Zeilen 24–25: Der Service ist eine Bean (annotiert mit [@Component]) und damit ein Singleton: Die Dateien werden nur einmal beim Start gelesen. Er implementiert das Interface [MessageSource] von [Spring] und heißt [messageSource], wie von der Annotation festgelegt. Dieser Name ist nicht zufällig gewählt: Unter diesem Namen sucht [Spring] den Übersetzungs-Service der Anwendung. [Spring Boot], das standardmäßig einen erzeugt (er würde die Dateien [messages*.properties] lesen), verzichtet darauf, sobald eine Bean mit diesem Namen existiert;
    • Zeilen 27–28: die unterstützten Sprachen und die Standardsprache. [List.of] erzeugt eine schreibgeschützte Liste;
    • Zeile 31: der reguläre Ausdruck [\{(\w+)\}] (eine öffnende geschweifte Klammer, ein oder mehrere Wortzeichen, erfasst, eine schließende geschweifte Klammer), der Parameter in einem Text erkennt. In einem [Java]-String wird der Backslash als [\\] geschrieben. [Pattern.compile] parst ihn ein für alle Mal;
    • Zeile 34: für jede Sprache ein [Java]-Wörterbuch ([Map]), das jedem vollständigen Schlüssel ([HOME.HELLO]) seinen Text zuordnet;
    • Zeilen 36–46: Der Konstruktor liest die JSON-Dateien. [ClassPathResource] verweist auf eine Datei im Klassenpfad (siehe oben). Die Anweisung [try (...)] (bekannt als „try-with-resources“-Anweisung) schließt den in ihren Klammern geöffneten Stream am Ende des Blocks automatisch, auch wenn ein Fehler auftritt. Das Objekt [ObjectMapper] der Bibliothek [Jackson] (derjenigen, die [Spring] für JSON verwendet) parst den Text und wandelt ihn in einen [JsonNode]-Knotenbaum um;
    • Zeilen 49–52: die unterstützte Sprache, die einer beliebigen Sprache am nächsten kommt. Ein [Locale]-Objekt vom Typ [Java] bezeichnet eine Sprache, gegebenenfalls mit Angabe eines Landes ([fr], [en_US] ...); [getLanguage()] liefert ihren aus zwei Buchstaben bestehenden Code. Eine nicht unterstützte Sprache ([de]) ergibt die Standardsprache;
    • Zeilen 56–72: die Übersetzung. Der Schlüssel wird im Wörterbuch der angeforderten Sprache nachgeschlagen; wird er nicht gefunden, wird der Schlüssel selbst angezeigt ([getOrDefault]): Eine Lücke ist sofort auf dem Bildschirm sichtbar;
    • Zeilen 65–68: Die Parameter werden in einem Array [Object[]] als Paare (Name, Wert) gespeichert: [["name", "Marie"]]. Die Schleife ordnet sie zu einem Wörterbuch [name -> value]. Wir werden sehen, warum dieses etwas ungewöhnliche Format gewählt wurde;
    • Zeilen 70–71: [replaceAll] ersetzt jeden im Text gefundenen Parameter [{name}] durch das Ergebnis des Lambdas: den Wert des gleichnamigen Parameters ([r.group(1)] ist der in Klammern erfasste Teil) oder den Parameter selbst, unverändert, wenn er keinen Wert hat ([r.group()] ist der gesamte gefundene Text). [Matcher.quoteReplacement] schützt die Zeichen [$] und [\] , die ein Wert enthalten könnte und die für [replaceAll] sonst eine besondere Bedeutung haben;
    • Zeilen 75–84: Die Methode „flacht“ JSON ab: Das Objekt ["HOME": { "HELLO": "..." }] ergibt den Schlüssel [HOME.HELLO]. Sie ruft sich selbst auf (rekursive Methode), um verschachtelte Objekte zu durchlaufen. [properties()] liefert die Paare (Name, Wert) eines JSON-Objekts; [asString()] liefert den Wert eines Textes.

    @Override

    // eine durch mehrere mögliche Codes beschriebene Meldung (die Validierungsfehler):
    // der erste im Wörterbuch vorhandene Code gewinnt
    @Override
    public String getMessage(MessageSourceResolvable message, Locale locale) {
        Map<String, String> dictionary = dictionaries.get(language(locale));
        String[] codes = message.getCodes() == null ? new String[0] : message.getCodes();
        for (String code : codes) {
            if (dictionary.containsKey(code)) {
                return translate(code, message.getArguments(), locale);
            }
        }
        String defaultText = message.getDefaultMessage();
        return defaultText != null ? defaultText : (codes.length > 0 ? codes[0] : "");
    }
}
    • Zeilen 3–11: die beiden Methoden, die einen Code (einen Schlüssel) und seine Argumente in eine bestimmte Sprache übersetzen; sie rufen [translate] auf. Die Annotation [@Override] weist den Compiler an zu prüfen, dass tatsächlich eine Methode des Interface überschrieben wird;
    • Zeilen 15–26: Die dritte Methode erhält ein Objekt [MessageSourceResolvable], das eine Nachricht anhand mehrerer möglicher Codes beschreibt, vom spezifischsten bis zum allgemeinsten. So beschreibt [Spring] Validierungsfehler (siehe Beispiel 19): Eine Einschränkung [@NotBlank] für das Feld [name] eines Objekts [person] ergibt die Codes [NotBlank.person.name], [NotBlank.name], [NotBlank] ... Der erste im Wörterbuch vorhandene Code hat Vorrang; ist keiner vorhanden, wird die Standardnachricht oder der erste Code zurückgegeben. Die Fallstudie nutzt dies, um ihre Fehlermeldungen zu übersetzen.

    In [Spring] ist das übliche Format für Nachrichtenparameter positionsbasiert: [Hello {0}!], wobei das erste Argument [{0}] ersetzt. Wir bevorzugen benannte Parameter, die in einem Wörterbuch lesbarer sind ([Hello {name}!]) und mit denen in den anderen Versionen der Fallstudie identisch sind. Das Interface [MessageSource] übergibt jedoch nur ein Array von Argumenten – daher die Konvention von (Name, Wert)-Paaren.

    5.1.3. Übersetzen in Views

    In einer [Thymeleaf]-View ist der Ausdruck [#{KEY}] – in Beispiel 14 bereits kurz mit dem Array eingeführt – die Übersetzung des Schlüssels [KEY] in die Sprache der Anfrage: [Thymeleaf] ruft die Bean [messageSource] auf, also unseren [Translator]. Argumente werden in Klammern übergeben: [#{HOME.HELLO('name', ${name})}] ruft [getMessage("HOME.HELLO", ["name", "Marie"], language)] auf. Auf der View-Seite müssen keine Klassen geschrieben werden – das ist der Vorteil, das [Spring]-Interface implementiert zu haben.

import java.text.NumberFormat;
import java.time.LocalDate;

import java.time.format.FormatStyle;

import org.springframework.context.i18n.LocaleContextHolder;
import org.springframework.stereotype.Component;

// Daten und Beträge, in der Sprache der Anfrage formatiert (siehe Beispiel 16)
@Component("formats")
public class Formats {

    // ein Datum in ausgeschriebener Form
    public String longDate(LocalDate date) {
        return date.format(DateTimeFormatter.ofLocalizedDate(FormatStyle.FULL).withLocale(LocaleContextHolder.getLocale()));

    // ein Betrag in Euro
    public String money(BigDecimal amount) {

    }
}

// die Konfiguration von Spring MVC, ergänzt
@Configuration
public class WebConfig implements WebMvcConfigurer {

    // Bootstrap, von den Beispielen gemeinsam genutzt: der Ordner examples/common/bootstrap

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {

                // "file:": ein Ordner auf der Festplatte, relativ zum aktuellen Ordner. Zwei

    // die Sprache jeder Anfrage: die des Cookies [language], sonst Englisch.
    // Die Bean muss [localeResolver] heißen: unter diesem Namen sucht Spring sie.
    @Bean
    public LocaleResolver localeResolver() {
        CookieLocaleResolver resolver = new CookieLocaleResolver("language");
        resolver.setDefaultLocale(Locale.ENGLISH);
        resolver.setCookieMaxAge(Duration.ofDays(365));
        resolver.setCookieHttpOnly(true);
        resolver.setCookieSameSite("Lax");
        return resolver;
    }
}

    package example22.controllers;

import java.net.URI;
import java.util.Locale;

import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.server.ResponseStatusException;
import org.springframework.web.servlet.LocaleResolver;

import example22.translation.Translator;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

@Controller
public class LanguageController {

    private final LocaleResolver localeResolver;

    public LanguageController(LocaleResolver localeResolver) {
        this.localeResolver = localeResolver;
    }

    // GET /language/fr: speichert die Auswahl in einem Cookie und kehrt dann zur vorherigen Seite zurück
    @GetMapping("/language/{language}")
    public String change(@PathVariable String language, HttpServletRequest request, HttpServletResponse response) {
        if (!Translator.LANGUAGES.contains(language)) {
            throw new ResponseStatusException(HttpStatus.NOT_FOUND);
        }
        // der LocaleResolver schreibt sein Cookie selbst (Name, Wert, Lebensdauer ...)
        localeResolver.setLocale(request, response, Locale.forLanguageTag(language));
        return "redirect:" + originPage(request);
    }

    // die Seite, von der wir kommen (Referer-Header), von der wir nur den Pfad behalten:
    // eine Weiterleitung auf eine vollständige, der Anfrage entnommene Adresse würde es
    // erlauben, den Benutzer auf eine andere Website zu schicken (Schwachstelle "Open Redirect")
    private static String originPage(HttpServletRequest request) {
        String referer = request.getHeader("Referer");
        try {
            URI url = URI.create(referer);
            String path = url.getRawPath();
            // "//site.com/..." würde vom Browser als Adresse
            // auf einer ANDEREN Website verstanden: ebenfalls abgelehnt
            if (path == null || !path.startsWith("/") || path.startsWith("//")) {
                return "/";
            }
            return url.getRawQuery() == null ? path : path + "?" + url.getRawQuery();
        } catch (RuntimeException e) {
            // kein Referer-Header (NullPointerException) oder eine ungültige Adresse
            return "/";
        }
    }
}

    Gehen wir diesen Code durch:

    • Zeilen 20–24: Der Controller erhält [LocaleResolver] per Dependency Injection;
    • Zeilen 27–35: [GET /language/fr] speichert die Auswahl in einem Cookie und leitet dann auf die Seite um, von der der Benutzer kam. Eine unbekannte Sprache löst einen 404-Fehler aus ([ResponseStatusException], siehe Beispiel 21);
    • Zeile 33: Wir erzeugen das Cookie nicht selbst, sondern bitten [LocaleResolver] darum, die Sprache zu ändern; er schreibt das Cookie mit dem Namen und den Eigenschaften, die in [WebConfig] festgelegt sind. [Locale.forLanguageTag("en")] erzeugt das Objekt [Locale] für Englisch;
    • Zeile 34: [redirect:] fordert eine Umleitung an (siehe Beispiel 04);
    • Zeilen 40–55: Die ursprüngliche Seite wird durch den Header [Referer] angegeben, den der Browser beim Klick auf einen Link hinzufügt. Wir behalten nur den Pfad und die Parameter ([getRawPath], [getRawQuery]: so, wie sie in der Adresse stehen, ohne Decodierung). Eine Umleitung auf eine vollständige URL aus der Anfrage würde es einer bösartigen Site erlauben, einen Link zu erstellen, der den Benutzer nach dem Durchgang durch unsere Site auf die bösartige Site weiterleitet (eine Schwachstelle, bekannt als [open redirect]);
    • Zeilen 45–49: Ein Pfad, der mit zwei Schrägstrichen beginnt, wird ebenfalls abgelehnt: Der Browser würde [//pirate.example/trap] als die Adresse [http://pirate.example/trap] auf einer anderen Site interpretieren;
    • Zeilen 51–54: Ohne den Header [Referer] löst [URI.create(null)] eine [NullPointerException] aus; eine ungültige Adresse eine [IllegalArgumentException]. Beide sind von [RuntimeException] abgeleitet: Man gelangt dann zurück auf die Startseite.

    package example22.controllers;

import java.math.BigDecimal;
import java.time.LocalDate;
import java.util.List;

import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;

// die Actions wissen nichts über die Sprache: sie liefern Daten,
// die Views übersetzen und formatieren sie
@Controller
public class PagesController {

    public record Product(String name, BigDecimal price) {
    }

    @GetMapping("/")
    public String home(Model model) {
        model.addAttribute("name", "Marie");
        model.addAttribute("today", LocalDate.of(2026, 9, 23));
        return "pages/home";
    }

    @GetMapping("/products")
    public String products(Model model) {
        model.addAttribute("products", List.of(
                new Product("Keyboard", new BigDecimal("25")),
                new Product("Mouse", new BigDecimal("12.5")),
                new Product("Screen", new BigDecimal("1149"))));
        return "pages/products";
    }
}

    Actions sind sprachunabhängig: Sie liefern Daten, während die Views sie übersetzen und formatieren. Der Preis ist ein [BigDecimal]; der [Java]-Typ für exakte Dezimalzahlen eignet sich für Geldbeträge (Zeile 16). Das Datum auf der Startseite ist ein festes Datum, der 23. September 2026 (Zeile 22), und nicht das aktuelle Datum: Die nachstehenden Ergebnisse hängen daher nicht vom Tag der Ausführung des Beispiels ab.
