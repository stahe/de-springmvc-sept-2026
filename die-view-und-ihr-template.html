    4. Die View und ihr Template

    Bisher haben die Actions ihre Antworten selbst erzeugt: Text, JSON und einige als Zeichenkette geschriebene HTML-Tags. In einer MVC-Anwendung ist dies die Aufgabe einer View: einer Datei, die die HTML-Seite beschreibt, mit Platzhaltern für die Daten, die ihr die Action übergibt – das Modell der View. [Spring MVC] stellt selbst keine View-Sprache bereit: Es kann mit mehreren View-Engines ([Thymeleaf], [FreeMarker], [Mustache], [JSP] ...) arbeiten. Dieser Kurs verwendet [Thymeleaf], die zusammen mit [Spring MVC] am weitesten verbreitete View-Engine, die [Spring Boot] selbstständig konfigurieren kann.

    Eine [Thymeleaf]-View ist eine gewöhnliche [.html]-Datei: eine gültige HTML-Datei, die unverändert in einem Browser geöffnet werden kann. Daten werden über zusätzliche Attribute mit dem Präfix [th:] ([th:text], [th:if], [th:each] ...) eingefügt, die [Thymeleaf] auf dem Server ausführt und anschließend aus der Seite entfernt. [Thymeleaf] bezeichnet dies als natürliche Templates ([natural templates]): Ein Grafikdesigner kann an der View arbeiten, ohne die Anwendung zu starten, und der Entwickler fügt ihr die Attribute [th:] hinzu. Das unterscheidet sich von [Razor], der View-Engine von [ASP.NET Core MVC], die HTML und [C#]-Code kombiniert, dem das Zeichen [@] vorangestellt ist.

    package example13.controllers;

import java.time.LocalTime;
import java.time.format.DateTimeFormatter;
import java.util.Map;

import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.servlet.ModelAndView;

import example13.models.PageModel;

// @Controller: die Actions geben den NAMEN einer View zurück
@Controller
public class ViewsController {

    private static final DateTimeFormatter TIME = DateTimeFormatter.ofPattern("HH:mm:ss");

    // Model: das Modell der View, ein von der Action gefülltes Dictionary;
    // der zurückgegebene String ist der Name der View: templates/views/index.html
    @GetMapping("/")
    public String index(Model model) {
        PageModel pageModel = new PageModel(
                "My first view",
                "This page was built by Thymeleaf, on the server.",
                LocalTime.now().format(TIME));
        model.addAttribute("model", pageModel);
        return "views/index";
    }

    // ModelAndView: die View, ihr Modell und gegebenenfalls der Antwortcode in einem einzigen Objekt
    @GetMapping("/hello/{name}")
    public ModelAndView hello(@PathVariable String name) {
        if (name.equals("unknown")) {
            return new ModelAndView("views/unknown", Map.of("name", name), HttpStatus.NOT_FOUND);
        }
        PageModel pageModel = new PageModel(
                "Hello " + name,
                "This time, the action built a ModelAndView object.",
                LocalTime.now().format(TIME));
        return new ModelAndView("views/index", Map.of("model", pageModel));
    }
}

    Lassen Sie uns diesen Code kommentieren:

    • Zeile 17: Die Annotation [@Controller] ersetzt die Annotation [@RestController] der vorherigen Beispiele. Mit [@RestController] ist das, was eine Action zurückgibt, die Antwort (Text, JSON). Mit [@Controller] gibt eine Action, die eine Zeichenkette zurückgibt, den Namen einer View zurück: Die View erzeugt dann die Antwort;
    • Zeile 25: Die Action erhält einen Parameter vom Typ [Model], bereitgestellt von [Spring MVC]. Das ist das Modell der View: ein Dictionary, in dem jeder Eintrag (ein Attribut) einen Namen mit einem Objekt verknüpft;
    • Zeilen 26–30: Die Action erzeugt ein [PageModel]-Objekt (einen Titel, eine Meldung, die aktuelle Uhrzeit) und legt es unter dem Namen [model] im Modell ab. Die View ruft es unter diesem Namen ab;
    • Zeile 31: Die Action gibt den Namen der View zurück, [views/index]. Sie erzeugt die Antwort nicht mehr selbst, sondern verweist auf eine View und hat deren Daten vorbereitet;
    • Zeile 36: Die Action [hello] gibt ein Objekt [ModelAndView] zurück, das den Namen der View und ihr Modell in einem einzigen Objekt vereint. Das ist eine weitere Möglichkeit, eine Action zu schreiben, die eine View verwendet;
    • Zeile 38: Hängt die View von der Anfrage ab, wählt die Action die View aus. Hier zeigt der Name [unknown] die View [views/unknown] an, mit dem Statuscode 404: Das dritte Argument des Konstruktors von [ModelAndView] ist der Antwortcode. Das Modell dieser View enthält eine einfache Zeichenkette: den angeforderten Namen. [Map.of(...)] erzeugt ein schreibgeschütztes Dictionary;
    • Zeile 44: Die beiden Actions teilen sich dieselbe View, [views/index], mit unterschiedlichen Modellen.

    Wo sucht [Spring MVC] nach der View [views/index]? Es übergibt den Namen der View an einen View-Resolver ([ViewResolver]), der ihn in eine konkrete View umwandelt. Der von [Spring Boot] für [Thymeleaf] ([ThymeleafViewResolver]) konfigurierte Resolver fügt ein Präfix, [classpath:/templates/], und ein Suffix, [.html], hinzu: Die View [views/index] ist die Datei [templates/views/index.html] im Classpath – das heißt in den Ordnern und Archiven, in denen die virtuelle [Java]-Maschine nach den Klassen und Ressourcen der Anwendung sucht. Der Ordner [src/main/resources] des Projekts gehört dazu: Sein Inhalt wird von [Maven] zusammen mit den kompilierten Klassen nach [target/classes] kopiert. Diese beiden Werte lassen sich in [application.properties] ändern (Eigenschaften [spring.thymeleaf.prefix] und [spring.thymeleaf.suffix]). Anders als bei [ASP.NET Core MVC] gibt es keine Konvention, die den Namen der View aus den Namen von Controller und Action ableitet: Die Action gibt stets den Pfad zur View an, relativ zum Ordner [templates].     Lassen Sie uns diesen Code kommentieren:

    • Zeile 2: Ein [Thymeleaf]-Kommentar wird als [<!--/* ... */-->] geschrieben. Das ist ein HTML-Kommentar, dessen Inhalt von [/*] und [*/] eingeschlossen wird: [Thymeleaf] entfernt ihn aus der gerenderten Seite, während ein gewöhnlicher HTML-Kommentar ([<!-- -->]) an den Browser gesendet würde;
    • Zeile 3: Das Attribut [xmlns:th] deklariert den Namensraum für die Attribute [th:]. Es ist ausschließlich für Code-Editoren gedacht (Autovervollständigung, Validierung): [Thymeleaf] verarbeitet die Attribute [th:] auch ohne es und entfernt es aus der erzeugten Seite;
    • Zeile 6: Das Attribut [th:text] ersetzt den Inhalt des Tags durch den Wert des Ausdrucks. [${model.title}] ist ein Variablenausdruck: [model] ist das von der Action gesetzte Attribut des Modells, und [.title] ruft dessen Zugriffsmethode auf, [title()]. Der im Tag stehende Text „Page Title“ ist nur ein Beispiel, das angezeigt wird, wenn die Datei direkt in einem Browser geöffnet wird; er verschwindet aus der erzeugten Seite;
    • Zeilen 9–11: Dasselbe Prinzip gilt für Titel, Meldung und Uhrzeit. Um einen Wert mitten in einen Text einzufügen, umgeben Sie ihn mit einem [<span>]-Tag, das das Attribut [th:text] trägt.

    [${...}]-Ausdrücke werden in der [Spring]-Ausdruckssprache geschrieben, [SpEL] ([Spring Expression Language]). [model.title] ruft die Methode [getTitle()] einer [JavaBean] oder die Methode [title()] eines Records auf: In beiden Fällen wird derselbe Code geschrieben.

    Eine [Thymeleaf]-View wird nicht mit der Anwendung kompiliert: Sie wird beim Aufruf der Seite gelesen und interpretiert. Ein Fehler in einer View wird daher nicht zur Kompilierzeit gemeldet, sondern erst bei der Anzeige der Seite. Wenn Sie [${model.titl}] in die View schreiben, schlägt die Anfrage fehl (Statuscode 500), und die Serverkonsole zeigt Folgendes an: [Property or field 'titl' cannot be found on object of type 'example13.models.PageModel']. Ebenso verursacht ein View-Name, der keiner Datei entspricht, den Fehler [Error resolving template [views/missing], template might not exist or might not be accessible by any of the configured Template Resolvers].     Lassen Sie uns diesen Code kommentieren:

    • Zeile 8: Das Attribut [th:with] deklariert lokale Variablen, die innerhalb des Tags, das es enthält, und in allen seinen untergeordneten Tags verwendet werden können – hier [total] und [count] – im gesamten Body der Seite. [model.products.![price]] ist eine Projektion von [SpEL]: die Liste der Produktpreise. [#aggregates] und [#lists] sind Hilfsobjekte von [Thymeleaf] (sie beginnen mit [#]): [#aggregates.sum] berechnet die Summe einer Liste von Zahlen; [#lists.size] zählt die Elemente einer Liste;
    • Zeilen 10–11: ein [Thymeleaf]-Kommentar, der in der erzeugten Seite nicht enthalten ist;
    • Zeile 12: Ein Wert [null] ([${model.nickname}]) zeigt nichts an, ohne Fehler;
    • Zeilen 14–15: [th:text] maskiert die Sonderzeichen in HTML ([<] wird zu [&lt;] ...): Der Text wird unverändert angezeigt. [th:utext] ([unescaped text]) fügt ihn ohne Maskierung ein: Er wird als HTML interpretiert. [th:utext] wird nur für HTML verwendet, das von der Anwendung erzeugt wurde, niemals für Daten, die ein Benutzer eingegeben hat: Der Benutzer könnte HTML oder sogar [JavaScript] in die Seite einschleusen (ein Angriff, bekannt als [XSS], [cross-site scripting]);
    • Zeilen 17–18: eine Bedingung. [th:if] behält das Tag (und seinen Inhalt), wenn der Ausdruck wahr ist, und entfernt es andernfalls; [th:unless] tut das Gegenteil. Es gibt kein [th:else]: Man schreibt die gegenteilige Bedingung;
    • Zeile 22: eine Schleife. Das Attribut [th:each] wiederholt das Tag, das es enthält – hier [<li>] –, einmal für jedes Element der Liste. [product] ist das aktuelle Element; [stat], das optional ist, ist der Iterationszähler: [stat.index] (beginnend bei 0), [stat.count] (beginnend bei 1), [stat.size], [stat.first], [stat.last], [stat.even], [stat.odd].             new Book("Le Rouge et le Noir", "Stendhal", "novel"),
            new Book("Les Fleurs du mal", "Baudelaire", "poetry"),
            new Book("Madame Bovary", "Flaubert", "novel"),
            new Book("Alcools", "Apollinaire", "poetry"),
            new Book("Le Cid", "Corneille", "drama"));

    // GET / und GET /search?keyword=...&genre=...: das Formular UND seine Ergebnisse
    @GetMapping({ "/", "/search" })
    public String search(@RequestParam(required = false) String keyword,
            @RequestParam(required = false) String genre, Model model) {
        String word = keyword == null ? "" : keyword.trim().toLowerCase(Locale.ROOT);
        List<Book> results = BOOKS.stream()
                .filter(b -> word.isEmpty() || b.title().toLowerCase(Locale.ROOT).contains(word)
                        || b.author().toLowerCase(Locale.ROOT).contains(word))
                .filter(b -> genre == null || genre.isEmpty() || b.genre().equals(genre))
                .toList();
        model.addAttribute("model", new SearchModel(keyword == null ? "" : keyword,
                genre == null ? "" : genre, GENRES, results));
        return "books/search";
    }
}

    4.8. Beispiel 20: Das Post/Redirect/Get-Muster

    Wird ein POST-Formular erfolgreich gesendet, kann die Action direkt eine Seite anzeigen. Das Problem entsteht, wenn der Benutzer diese Seite anschließend neu lädt (Taste F5): Der Browser sendet das Formular erneut, und die Operation wird ein zweites Mal ausgeführt (eine doppelt aufgegebene Bestellung, ein doppelt vereinbarter Termin ...). Das Post/Redirect/Get-Muster (PRG) verhindert dieses Problem: Eine erfolgreiche POST-Action erzeugt keine Seite, sondern leitet auf eine GET-Seite um. Das erneute Laden dieser Seite löst lediglich ein weiteres GET ohne Auswirkung aus.

    Ein Detail bleibt: Die GET-Seite muss eine Meldung anzeigen („Die Aufgabe wurde hinzugefügt“), obwohl diese Meldung von der POST-Action in einer anderen Anfrage erzeugt wurde. [Spring MVC] stellt hierfür die Flash-Attribute bereit: Attribute, die vor der Umleitung gesetzt werden und bis zur nächsten Anfrage erhalten bleiben, wo sie dem Template hinzugefügt werden und dann verschwinden. Man spricht von einer Flash-Meldung. Standardmäßig speichert [Spring MVC] die Flash-Attribute in der HTTP-Session des Benutzers: einem Speicherbereich, den der Server jedem Browser zuordnet (dem Kapitel „Datenbereiche“ ist dieses Thema gewidmet).

    // POST /tasks: das Muster Post / Redirect / Get
    @PostMapping("")
    public String add(@RequestParam(required = false) String label, Model model,
            RedirectAttributes redirect) {
        String text = label == null ? "" : label.trim();
        if (text.isEmpty() || text.length() > 40) {
            // ungültige Eingabe: wir zeigen die Seite erneut an, ohne Weiterleitung

    package example21.services;

import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

import org.springframework.stereotype.Service;

// die Kontakte, im Speicher, von allen gemeinsam genutzt (Singleton)
@Service
public class ContactsService {

    // ein Kontakt: eine Kennung, ein Name, eine Telefonnummer
    public record Contact(int id, String name, String phone) {
    }

    private final List<Contact> contacts = new ArrayList<>(List.of(
            new Contact(1, "Marie Durand", "01 23 45 67 89"),
            new Contact(2, "Paul Martin", "06 12 34 56 78"),
            new Contact(3, "Philippe Jandot", "02 98 76 54 32")));
    private int lastId = 3;

    // synchronized: jeweils nur eine Anfrage führt die Methode aus
    public synchronized List<Contact> list() {
        return List.copyOf(contacts);
    }

    // Optional: ein Kontakt oder "nichts", wenn er nicht existiert
    public synchronized Optional<Contact> read(int id) {
        return contacts.stream().filter(c -> c.id() == id).findFirst();
    }

    public synchronized Optional<Contact> edit(int id, String name, String phone) {
        for (int i = 0; i < contacts.size(); i++) {
            if (contacts.get(i).id() == id) {
                // ein Record ist unveränderlich: wir ersetzen ihn durch einen neuen
                Contact edited = new Contact(id, name, phone);
                contacts.set(i, edited);
                return Optional.of(edited);
            }
        }
        return Optional.empty();
    }

    public synchronized Contact add(String name, String phone) {
        Contact contact = new Contact(++lastId, name, phone);
        contacts.add(contact);
        return contact;
    }

    public synchronized Optional<Contact> delete(int id) {
        Optional<Contact> contact = read(id);
        contact.ifPresent(contacts::remove);
        return contact;
    }
}

import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.server.ResponseStatusException;
import org.springframework.web.servlet.mvc.support.RedirectAttributes;

import example21.services.ContactsService;
import example21.services.ContactsService.Contact;

@Controller
@RequestMapping("/contacts")
public class ContactsController {

    private final ContactsService contacts;

    public ContactsController(ContactsService contacts) {
        this.contacts = contacts;
    }

    // ein LINK (<a href>): eine GET-Anfrage, die nichts verändert
    @GetMapping("")
    public String list(Model model) {
        model.addAttribute("contacts", contacts.list());
        return "contacts/list";
    }

    @GetMapping("/{id:\\d+}")
    public String details(@PathVariable int id, Model model) {
        model.addAttribute("contact", contacts.read(id).orElseThrow(ContactsController::notFound));
        return "contacts/details";
    }

    // ein BUTTON in einem POST-Formular: eine Anfrage, die Daten verändert
    @PostMapping("/{id:\\d+}")
    public String save(@PathVariable int id, @RequestParam String name, @RequestParam String phone,
            RedirectAttributes redirect) {
        Contact contact = contacts.edit(id, name, phone).orElseThrow(ContactsController::notFound);
        redirect.addFlashAttribute("flash", "The contact [" + contact.name() + "] has been edited.");
        return "redirect:/contacts";
    }

    // dasselbe Formular, ein anderer Button (Attribut formaction): eine andere Action
    @PostMapping("/{id:\\d+}/duplicate")
    public String duplicate(@PathVariable int id, @RequestParam String name, @RequestParam String phone,
            RedirectAttributes redirect) {
        Contact copy = contacts.add(name + " (copy)", phone);
        redirect.addFlashAttribute("flash", "The contact [" + copy.name() + "] has been created.");
        return "redirect:/contacts";
    }

    @PostMapping("/{id:\\d+}/delete")
    public String delete(@PathVariable int id, RedirectAttributes redirect) {
        Contact contact = contacts.delete(id).orElseThrow(ContactsController::notFound);
        redirect.addFlashAttribute("flash", "The contact [" + contact.name() + "] has been deleted.");
        return "redirect:/contacts";
    }

    // eine Exception, die eine 404-Antwort erzeugt
    private static ResponseStatusException notFound() {
        return new ResponseStatusException(HttpStatus.NOT_FOUND, "unknown contact");
    }
}

    // Bestätigung der Formulare, die das Attribut data-confirmation="..." tragen
// Ohne JavaScript werden diese Formulare einfach ohne Bestätigung gesendet.
(() => {
  const modal = document.getElementById('confirmation-modal');
  const message = document.getElementById('confirmation-modal-message');
  let pending = null; // das Formular, das gesendet wird, wenn der Benutzer bestätigt

  // 1. wir fangen das Absenden der zu bestätigenden Formulare ab
  document.querySelectorAll('form[data-confirmation]').forEach((form) => {
    form.addEventListener('submit', (event) => {
      event.preventDefault(); // das Absenden wird angehalten
      pending = form;
      message.textContent = form.dataset.confirmation;
      modal.classList.remove('d-none'); // das Fenster erscheint
    });
  });

  // 2. die beiden Buttons des Fensters
  modal.addEventListener('click', (event) => {
    const action = event.target.dataset.action;
    if (action === 'yes') {
      pending.submit(); // Absenden, OHNE das Ereignis 'submit' erneut auszulösen
    } else if (action === 'no') {
      modal.classList.add('d-none');
      pending = null;
    }
  });
})();
    • Zeile 3: Der Code ist in eine Funktion eingebettet, die sofort ausgeführt wird, um keine globalen Variablen zu erzeugen;
    • Zeilen 9–16: Das Absenden jedes Formulars mit dem Attribut [data-confirmation] wird abgefangen. [preventDefault()] unterbricht das Absenden; das Formular wird gemerkt, die Frage wird im Fenster platziert ([textContent], nicht [innerHTML]: Die Frage wird als Text angezeigt und niemals als HTML interpretiert), und das Fenster wird angezeigt;
    • Zeilen 19–27: „Ja“ sendet das gemerkte Formular ab. Die Methode [submit()] eines Formulars sendet es ab, ohne das Ereignis [submit] auszulösen: Es erscheint keine erneute Bestätigungsabfrage. „Nein“ blendet das Fenster aus.
