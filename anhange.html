    13. Anhänge

    13.1. Installation von JDK 21

    Das [JDK] ([Java Development Kit]) enthält den Compiler [javac] und die virtuelle Maschine [java]. Es gibt mehrere kostenlose Distributionen; wir verwenden [Eclipse Temurin] aus dem Projekt [Adoptium], das von adoptium.net heruntergeladen werden kann: Wählen Sie Version 21 (LTS) und dann den Installer für Ihr System ([Windows] x64, [macOS], [Linux]).

    Unter [Windows] bietet der [.msi]-Installer auf dem Anpassungsbildschirm die Option „Set JAVA_HOME variable“ an; diese Option ist standardmäßig deaktiviert – Sie müssen sie aktivieren. Die Umgebungsvariable [JAVA_HOME] gibt den Speicherort des [JDK] an; der Maven Wrapper nutzt sie, um [Java] zu finden. Sie können auch den Paketmanager [winget] verwenden:

    1
    winget install EclipseAdoptium.Temurin.21.JDK

    Unter [macOS] verwenden Sie den Installer [.pkg] von derselben Seite oder den Paketmanager [Homebrew] ([brew install --cask temurin@21]). Unter [Linux] ([Ubuntu] zum Beispiel) eignet sich das Paket [openjdk-21-jdk] aus den Repositories der Distribution:

    1
    sudo apt install openjdk-21-jdk

    Prüfen Sie die Installation in einer neuen Konsole ([PowerShell], Eingabeaufforderung oder Terminal):

    1
    java -version

    Es sollte eine Versionsnummer anzeigen, die mit 21 beginnt (zum Beispiel [openjdk version "21.0.10"]). Ein neueres [JDK] (zum Beispiel 25) funktioniert ebenfalls; ein älteres [JDK] (zum Beispiel 17) führt bei der Kompilierung zum Fehler [release version 21 not supported].

    13.2. Maven und der Maven Wrapper

    Es muss nichts installiert werden: Der Ordner [examples] und der Ordner der Fallstudie enthalten jeweils den Maven Wrapper, die Skripte [mvnw] ([Linux], [macOS]) und [mvnw.cmd] ([Windows]) sowie die Datei [.mvn/wrapper/maven-wrapper.properties], die die zu verwendende Version von [Maven] festlegt (3.9.11). Beim ersten Ausführen lädt das Skript diese Version von [Maven] herunter und speichert sie im Home-Verzeichnis des Benutzers (Ordner [.m2/wrapper]); bei späteren Ausführungen wird sie wiederverwendet. [Maven] lädt seinerseits die Bibliotheken des Projekts aus dem Repository Maven Central herunter und speichert sie im Ordner [.m2/repository]. Beim ersten Kompilieren ist daher eine Internetverbindung erforderlich.

    Der Maven Wrapper benötigt [Java]: Er verwendet das [JDK] aus der Variablen [JAVA_HOME] oder, falls diese fehlt, den im Pfad gefundenen Befehl [java] ([PATH]). Um zu prüfen, ob alles vorhanden ist, kompilieren Sie alle Beispiele aus dem Ordner [examples]:

    1
    ./mvnw compile

    ([.\mvnw compile] unter [Windows]). Der Befehl endet mit [BUILD SUCCESS].

    Wenn Sie [Maven] lieber selbst installieren (maven.apache.org), ersetzt der Befehl [mvn] in allen Befehlen des Dokuments [mvnw].

    13.3. Installation von Visual Studio Code

    Laden Sie [Visual Studio Code] von code.visualstudio.com herunter. Fügen Sie zwei Erweiterungen hinzu (Menü Ansicht > Erweiterungen, dann nach ihren Namen suchen):

    • [Extension Pack for Java] von Microsoft: eine Sammlung von Erweiterungen, die Syntaxhervorhebung, Code-Vervollständigung und Fehlermeldungen für [Java]-Code bietet; Unterstützung für [Maven]-Projekte (Bereich „Java Projects“); den Debugger und die automatische Kompilierung jeder gespeicherten Datei;
    • [Spring Boot Extension Pack] von VMware (marketplace.visualstudio.com): Autovervollständigung für Properties in [application.properties], Navigation zwischen Beans und URL-Controllern sowie den Bereich „Spring Boot Dashboard“, der die [Spring Boot] -Anwendungen im geöffneten Ordner auflistet und es erlaubt, jede mit einem einzigen Klick zu starten oder zu stoppen.

    Öffnen Sie den Ordner [examples] oder den Ordner der Fallstudie (Menü Datei / Ordner öffnen); im integrierten Terminal (Menü Terminal / Neues Terminal) können Sie [mvnw]-Befehle ausführen, ohne den Editor zu verlassen. Die Taste F5 führt in der Startklasse einer Anwendung (der mit [@SpringBootApplication] annotierten) die Anwendung unter der Kontrolle des Debuggers aus.

    13.4. Installation von MySQL mit Laragon

    [Laragon] (laragon.org) installiert einen gebrauchsfertigen [MySQL]-Server (oder [MariaDB]) zusammen mit dem Verwaltungswerkzeug [HeidiSQL]. Nach der Installation:

    • Die Schaltfläche „Alles starten“ startet den [MySQL]-Server auf Port 3306;
    • Der Benutzer [root] hat kein Passwort: Das sind die Standardwerte der Properties [spring.datasource.*] aus Beispiel 28 und der Fallstudie;
    • Die Schaltfläche „Datenbank“ öffnet [HeidiSQL], wo der Menüpunkt Datei / SQL-Datei ausführen die Skripte [dbpersons.sql] (Beispiel 28) und [dbrdvmedecins2.sql] (Fallstudie) ausführt.

    Unter [Linux] oder [macOS] installieren Sie [MySQL] oder [MariaDB] mit dem Paketmanager des Systems und führen die Skripte mit dem Kommandozeilen-Client [mysql] aus. Der [JDBC] -Treiber von [MySQL] funktioniert auch ohne jede Konfiguration mit [MariaDB]: [Hibernate] zeigt beim Start lediglich die Warnung [HHH000511] an, ohne Folgen (siehe Beispiel 28).

    13.5. Installation von curl

    [curl] ist in [Windows] 10 und 11, [macOS] und den meisten [Linux]-Distributionen enthalten. In [PowerShell] müssen Sie [curl.exe] eingeben, nicht [curl]: In älteren Versionen von [PowerShell] ist [curl] ein Alias für einen anderen Befehl ([Invoke-WebRequest]), der andere Optionen hat.
